自动将 Sukka 通用 List 规则转换为 Egern 原生 YAML Rule Set，并提供 iOS Lite 精简版本。

## 自动转换流程

1. 自动发现 `List/domainset`、`List/non_ip` 和 `List/ip`。
2. 并发下载上游规则，并在完整下载后原子写入。
3. 自动识别并删除 Sukka 域名 Marker 与关键词 Marker。
4. 转换为 Egern 官方规则集字段，并删除被上级域名覆盖的条目。
5. 在相同 no_resolve 语义分区内合并 IPv4 / IPv6 网段。
6. 检查混合 `no-resolve` 规则并输出严格语义拆分版本。
7. 生成排除大型广告列表和 URL 正则的 iOS Lite 规则。
8. 检查关键规则、历史数量下降和转换覆盖率。
9. 通过 YAML、Marker 残留、重复值、CIDR 和分类完整性校验。
10. 仅在 SHA256 发生变化时替换旧规则并提交。

```yaml

  - rule_set:
      match: "https://raw.githubusercontent.com/locksherneo/egern-sukka-rules/main/domain/apple_cdn.yaml"
      policy: DIRECT
      update_interval: 86400

  - rule_set:
      match: "https://raw.githubusercontent.com/locksherneo/egern-sukka-rules/main/non_ip/ai.yaml"

  - rule_set:

```

## 混合 no_resolve 规则的严格用法

Egern 的 `no_resolve` 是规则集级别开关，无法在同一个规则文件中
同时精确表达需要解析与禁止解析的 IP 条目。原文件名继续兼容旧配置；
如果需要严格保留上游语义，改为按以下顺序引用两个拆分文件。
若混合源文件还包含真实域名规则，则会额外生成 `.non_ip.yaml`，
应先引用该域名文件，再引用 `.no_resolve.yaml` 和 `.resolve.yaml`。

```yaml
rules:
  - rule_set:
      match: "https://raw.githubusercontent.com/locksherneo/egern-sukka-rules/main/ip/reject.no_resolve.yaml"
      policy: REJECT
      update_interval: 86400

  - rule_set:
      match: "https://raw.githubusercontent.com/locksherneo/egern-sukka-rules/main/ip/reject.resolve.yaml"
      policy: REJECT
      update_interval: 86400
```

仅对实际包含混合 `no-resolve` 语义的源文件生成拆分版本。
具体名单参见 `CONVERSION_REPORT.md` 与 `CONVERSION_AUDIT.json`。
完整严格语义引用片段见 `EGERN_RULES_STRICT.yaml`。

## 分类与建议顺序

1. `domain/`：纯域名规则。
2. `non_ip/`：域名、通配符、关键字和 URL 等非 IP 规则。
3. `ip/`：IPv4、IPv6、ASN 和 GeoIP 规则。
4. `lite/domain/`、`lite/non_ip/`、`lite/ip/`：iOS 轻量规则。

建议先放 `domain/` 和 `non_ip/`，最后放 `ip/`，减少提前 DNS 查询。
